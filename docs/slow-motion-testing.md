## 第一阶段：分离触发场景

每次只改变一个条件。重复场景前先确认上一段慢动作已经完全恢复；目前不预设需要等待多少秒。

| 测试 | 操作与对照 | 要记录的结果 |
| --- | --- | --- |
| 无事件基线 | 同一场景中移动、转动镜头，不触发战斗或拾取 | 正常状态下观察值是否稳定；哪些变化来自普通移动或镜头 |
| 进入战斗 | 从非战斗状态进入战斗，不同时攻击或拾取 | 触发时刻、警告行为、慢动作进入与结束 |
| 普通命中 | 已经处于战斗状态，命中但未击杀、未击昏、未造成肢体破坏 | 是否也有减速，作为击杀/击昏的对照 |
| 单次击昏 | 已经处于战斗状态，非致命击昏一名人类敌人，随后停止攻击 | 单次效果的变化曲线与持续时间 |
| 单次击杀 | 已经处于战斗状态，击杀一名人类敌人，随后停止攻击 | 与击昏在倍率、持续时间及写入来源上的异同 |
| 重复拾取 | 在无战斗、无 BT 遭遇干扰的场景中，分别测试电气虫和隐生虫的单次与重复拾取 | 哪次触发、拾取间隔、效果进入与恢复 |
| BT 遭遇 | 记录区域和警告模式，对照三种“遇敌动作”设置 | 完整/简化警告是否仍伴随时间变化 |
| 武器使用 | 记录武器实际使用历史，把切换、瞄准、开火与命中分开；先做没有敌人受伤的对照 | 是否存在独立触发；无法确定使用历史时不标记为首次 |
| 肢体破坏 | 尽量在目标未死亡、未击昏且上一段慢动作结束后观察，记录目标结果 | 是否有独立短暂减速；无法分离击杀/击昏时标记为混合事件 |

读取存档或重启游戏是否重置“首次”标记，也需要验证，不能默认它们会重置。

建议录制连续画面并记录事件发生时刻。单凭角色动画、镜头变化或声音，不能确认全局时间倍率变化。若可见信息不足，保留为未确认，等待内存证据。

## 第二阶段：观察连续触发

先测出单次事件的正常持续时间范围，再安排不同间隔的第二次事件：

- 第二次事件发生在第一段效果尚未结束时。
- 第二次事件发生在第一段效果刚结束后。
- 第二次事件发生在已经恢复正常一段时间后。

记录第一事件、第二事件、恢复正常三个时刻，并检查倍率是否再次变化以及是否出现新的写入。

需要区分的问题：

- 后续事件是否把结束时刻向后移动，且结束与最后一次事件的间隔接近单次效果时长？
- 后续事件是否增加剩余时长，而不是重新从头计时？
- 效果尚未结束时，后续事件是否没有延长效果？
- 只有达到某个事件间隔后才再次触发吗？
- 是否存在倍率保持不变、但计时或请求状态发生变化的情况？

这些现象只能帮助区分机制。重复写入同一低值不等于重置持续时间；还需要观察计时字段或请求状态。倍率稳定也不等于后续事件被忽略。

## 第三阶段：内存和写入来源定位

1. 不预设正常值一定为 `1.0`、慢动作一定低于 `1.0`，也不预设类型一定为 `float`。
2. 根据本机 CE 的实际值类型选项确定扫描方式，使用未知初始值、变化和未变化筛选建立事件前后的关联。取得数值规律后再使用精确值或增减关系。
3. 同时保留无事件基线和其他触发场景，排除只反映镜头、动画、界面或某个局部对象的值。
4. 短暂效果必须在仍然生效时取样。如果调试器暂停了进程，要记录暂停区间，不能将暂停耗时混入游戏效果持续时间。
5. 初步收敛后先观察，不立即冻结。关联成立仍不等于该地址控制全局时间。
6. 使用 CE 的写入追踪，分别采集开始、持续、重复事件和恢复时的命中记录。

每条有效记录至少保存：

- 精确模块名、运行时基址和指令 RVA。
- 指令文本、机器码、写入宽度、写入前后的实际值。
- 命中时的寄存器和调用栈，以及能够解释本次调用来源的实际参数。
- 对应的游戏事件、事件时刻、警告模式及是否存在其他同时发生的事件。

地址、字段偏移、函数签名及 JSON 路径等具体表述都从实际记录提取，不通过命名或格式推测。

## 已读取到的静态名称

此前从本机 `DS2.exe` 的字符串中读取到了以下精确名称，可在后续静态分析时查交叉引用：

- `DSTimeScaleControlConfig`
- `DSTimeScaleControlParameter`
- `RequestTimeScaleControl`
- `BeginAdrenalinBoostTimeScaleControlName`
- `ExtendAdrenalinBoostTimeScaleControlName`

目前没有证明这些名称对应击杀/击昏慢动作，也没有确认函数签名。它们不能直接用作 Hook 依据。

## 实现前必须解决的问题

- 各种触发场景是否汇入同一个通用时间控制逻辑？同一写入函数不代表同一请求来源。
- 能否通过已验证的请求、参数或调用路径区分击杀/击昏与其他效果？
- 单次效果的倍率、进入/退出变化和持续时间分别是什么？
- 连续击杀是刷新、叠加、忽略后续请求，还是其他行为？
- 拾取与武器的“首次”判定范围是什么？
- 肢体破坏的短暂效果是否真实且独立存在？
- 最终范围是否仍只禁用人类敌人击杀/击昏效果，其他慢动作是否保留？

不能仅凭 `0 < scale < 1` 判断来源。正式补丁必须先确认参数含义、调用约定及必要的状态清理，避免一并改变其他效果。
